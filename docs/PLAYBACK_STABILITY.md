# 播放稳定性与验收边界

电视真机验收由用户负责，包括实际观看、遥控交互、声音与音画同步及设备侧回退验证。助手完成已授权的实现与本地检查后交接，不主动安排、催验或反复索要整套验收记录，也不把用户验收列为助手未收尾任务。用户反馈问题时，结合描述查看已有日志和必要的单次、限量状态，不增加持续采集、采样或监测负担。反馈仅证明用户实际确认的范围；下文同条件对照由用户执行，基线、回滚和发布授权边界继续适用。

历史家庭稳定基线为 **0.2.40 / versionCode 53**，正式应用 ID 为 `com.kantv.app`。其 M3U 原生播放逻辑基于 0.2.37，保留当时已工作的 Gecko；正式包重诊断关闭。用户曾在 5X 验收通过，不代表所有设备、频道或音画同步测量已通过。

原始签名 APK、源码归档、哈希清单与家庭验收原件私有保留。公开历史不携带家庭端点与现场记录，亦不把历史私有提交或标签重新上传。`PLAYBACK_STABLE_SOURCE_V53.json` 保留原始源码文件哈希，作为历史对照标识，不表示当前开发树与它完全相同。

修改播放行为、依赖或保护调度后，须在相同设备、频道、实际线路、输出与网络条件下先运行原始基线，再测试候选。覆盖首次、持续播放、换台或前后台恢复，完整越过已知故障窗口。条件改变则重新建立对照。

- 单测、构建、下载成功或播放器存活不能代替可见播放、声音与音画同步验收。
- 不增加持续采集器、逐帧音画配对、画面回读、周期内存采样或追踪来代替真实验收。
- 模拟器源码控制用于代码可行性，不能称为原始签名 v53 真机对照。
- 未完成真实对照与实际验收的候选不得替换家庭稳定更新入口。
- 只有用户明确验收并要求更新基线后才更新当前指针；原始资料与回滚包始终保留。

当前开发候选与原始稳定包分别管理；公开源码整理不会执行 NAS 部署或更新入口切换。
