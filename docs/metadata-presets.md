# 节目单与台标预设

日期：2026-09-08。用户已要求补齐设置并评估预设；以下来源优先级与更新规则为建议，未视作用户确认。原型可选择预设，但不联网下载、不解析真实源、不保存到电视。

## 用户看到什么

EPG 就是电子节目单，菜单统一叫“节目单（EPG）”，避免让人以为节目单与 EPG 是两套功能。节目表是展示这些节目的页面。

- 播放列表：导入、管理，并关联节目单来源。
- 节目单（EPG）：来源、频道匹配、更新周期、立即更新、时间校正、最近更新状态。
- 频道台标：来源优先级、自动补全、单频道纠正、本地缓存。
- 诊断信息：更新失败原因、覆盖统计、最后成功时间；日常播放页面不显示这些详情。

原型已能用方向键在分类与设置行间移动，确认进入节目单来源/台标来源/更新周期选择，返回只退一层。其余行暂是功能说明，不伪装成已经实现的配置项。

## 建议预设行为

1. 初始优先播放列表明确指定的节目单和台标，手动修正最高优先级。XMLTV 频道标识与 M3U 的 `tvg-id` 精确关联；不能用频道显示序号代替。
2. 公共资料只用于补全缺失项。没有精确标识时，用经过维护的别名映射；繁简、空格、CCTV-1 等变体可以规范化，但不同地区/语言/节目版本不自动混在一起。多个可能匹配时留给家人选择。
3. 台标优先手动指定、列表内台标，再到已启用的补全库；失败用缓存，首次无图显示频道名。EPG 与台标不绑死在同一个公共站点。
4. 建议每天后台更新，支持手动更新；先下载临时文件，检查结构、时间范围与数据量，再替换当前资料。请求失败、空文件或解析失败保留上次成功版本。旧节目按日期展示，过期时显示暂无节目，不拿昨天节目冒充今天。
5. XMLTV 时区只换算一次；允许按来源校正。显示未匹配数、节目覆盖时间、最近成功/失败时间，避免只显示“更新成功”却没有当前节目。
6. 资料下载与播放任务分开调度，限制并发、文件大小、解压后大小和图片尺寸；解析不启用外部 XML 实体。资料库匹配在本地执行，不上传真实播放地址、列表或凭据。
7. 预设是有版本的本地来源清单，不是远程可执行插件。用户可关闭或覆盖，不自动更改真实播放源。候选服务尚未验证时不默认启用。

机器可读草案见 `config/metadata-presets.json`，记录来源和验证状态。进度注记（2026-09-28）：M3U 内的 `tvg-logo`/`tvg-id` 关联导入已实现，EPG 浮层已随枢纽订阅落地；预设库自动下载/匹配的状态以代码为准。端点是第三方公开元数据地址，不含用户直播源。

## 与 Kodi 的结合点

IPTV Simple 源码 `PlaylistLoader.cpp:333` 读取 tvg-id/name/logo，`Epg.cpp:465` 依次尝试 ID、tvg-name、频道名匹配，能作为资料关联的参考。kantv 建议对重名歧义更谨慎，并把家人手动纠正保存下来。

预设节目单、台标能减少家人配置工作，但不改善视频缓冲、解码或网络稳定性；播放策略仍按 `kodi-source-analysis.md` 独立落实。

阶段：P1 展示完整设置与选择流程；P2 导入并保留列表内的资料关联；P3 实现 XMLTV、预设下载、台标缓存和人工匹配。NAS 侧的节目单/台标抓取服务已由 `server/`（原 iptv-nas）承担，走独立部署范围。

验收：有/无 tvg-id、频道别名、重名、缺台标、时区错误、过期/空/损坏资料、断网缓存、手动纠正后更新不覆盖、两台设备访问能力。数据覆盖率与视频播放成功率分别报告。
